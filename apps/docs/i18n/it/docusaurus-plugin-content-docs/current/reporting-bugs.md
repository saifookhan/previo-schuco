# Segnalare un bug

Prima di segnalare, controlla [Non ancora realizzato](./known-gaps.md) — quelle cose sono note.

## Cosa includere

Una buona segnalazione permette a un'altra persona di vedere lo stesso problema in due minuti:

```text
Titolo:    <breve riepilogo — cosa non va, dove>

Utente:    <email utente demo, es. admin@suppli-demo.it>
Pagina/URL: <l'indirizzo nella barra del browser>
Lingua:    IT / EN / DE
Browser:   <Chrome / Safari / Firefox, desktop o telefono>

Passi:
1. …
2. …
3. …

Atteso:    <cosa doveva succedere>
Effettivo: <cosa è successo invece — copia eventuali messaggi di errore esattamente>

Screenshot / registrazione schermo: <allega>
```

## Consigli

- **Un problema per segnalazione.**
- Usa i **dati demo** quando puoi (es. "Demo Window W70, Finestra 1 anta, 1300 × 900") così i numeri
  si possono riprodurre.
- Per un prezzo sbagliato, indica **misura, quantità, opzioni, sconto e markup** — il valore atteso
  si può verificare con [Come vengono calcolati i prezzi](./pricing.md).
- Per un problema email, indica **quale indirizzo** e **quando** circa, e se è comparsa in [Mailpit](./email-mailpit.mdx).
- Se qualcosa "non salva", annota se è comparso un **messaggio di errore rosso** e cosa diceva.

## Dove inviarla

Inviala al team PREVIO nel solito canale del progetto. Gli sviluppatori possono anche aprire una issue
GitHub nel repository.
