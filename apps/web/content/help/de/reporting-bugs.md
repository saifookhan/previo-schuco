# Fehler melden

Vor dem Melden [Noch nicht umgesetzt](./known-gaps.md) prüfen — diese Dinge sind bekannt.

## Was dazugehört

Eine gute Meldung erlaubt es jemand anderem, dasselbe Problem in zwei Minuten zu sehen:

```text
Titel:       <kurze Zusammenfassung — was ist falsch, wo>

Benutzer:    <Demo-Benutzer, z. B. admin@suppli-demo.it>
Seite/URL:   <die Adresse in der Browserzeile>
Sprache:     IT / EN / DE
Browser:     <Chrome / Safari / Firefox, Desktop oder Handy>

Schritte:
1. …
2. …
3. …

Erwartet:    <was hätte passieren sollen>
Tatsächlich: <was stattdessen passiert ist — Fehlermeldungen genau kopieren>

Screenshot / Bildschirmaufnahme: <anhängen>
```

## Tipps

- **Ein Problem pro Meldung.**
- Wo möglich die **Demo-Daten** verwenden (z. B. „Demo Window W70, Finestra 1 anta, 1300 × 900“), damit
  die Zahlen nachvollziehbar sind.
- Bei einem falschen Preis **Maß, Menge, Optionen, Rabatt und Aufschlag** angeben — der erwartete Wert
  lässt sich mit [Wie Preise berechnet werden](./pricing.md) prüfen.
- Bei einem E-Mail-Problem **welche Adresse** und ungefähr **wann** angeben, und ob sie in [Mailpit](./email-mailpit.mdx) erschien.
- Wenn etwas „nicht speichert“, notieren, ob eine **rote Fehlermeldung** erschien und was darin stand.

## Wohin damit

An das PREVIO-Team im üblichen Projektkanal schicken. Entwickler können auch ein GitHub-Issue im Repository anlegen.
