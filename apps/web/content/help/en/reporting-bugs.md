# Reporting a bug

Before reporting, check [Not built yet](./known-gaps.md) — those are known.

## What to include

A good report lets someone else see the same problem in two minutes:

```text
Title:     <short summary — what is wrong, where>

Login:     <demo user email, e.g. admin@suppli-demo.it>
Page/URL:  <the address in the browser bar>
Language:  IT / EN / DE
Browser:   <Chrome / Safari / Firefox, desktop or phone>

Steps:
1. …
2. …
3. …

Expected:  <what should have happened>
Actual:    <what happened instead — copy any error message exactly>

Screenshot / screen recording: <attach>
```

## Tips

- **One problem per report.**
- Use the **demo data** where you can (e.g. "Demo Window W70, Finestra 1 anta, 1300 × 900") so the
  numbers can be reproduced.
- For a wrong price, include the **size, quantity, options, discount and markup** — the expected
  value can then be checked against [How prices are calculated](./pricing.md).
- For an email problem, say which **email address** and roughly **when**, and whether it showed up in
  [Mailpit](./email-mailpit.mdx).
- If something "doesn't save", note whether a **red error message** appeared and what it said.

## Where to send it

Send it to the PREVIO team in the project's usual channel. Developers can also open a GitHub issue
in the repository.
